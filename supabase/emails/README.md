# 메일 템플릿

Supabase 대시보드에 붙여넣는 HTML 이다. 코드가 읽지 않는다.
여기 둔 이유는 대시보드에서만 관리하면 기록이 남지 않고, 값이 바뀌어도 알 수 없기 때문이다.

## otp-code.html — 관리자 로그인 번호

### 어느 템플릿에 넣나 — 여기서 가장 많이 헷갈린다

> **Magic Link** 에 넣는다. Confirm signup 이 아니다.

로그인은 `signInWithOtp()` 로 한다. 이미 **확인된** 계정이면 Supabase 는
**Magic Link** 템플릿을 쓴다. 이름은 링크지만 본문에 `{{ .Token }}` 을 넣으면
6자리 번호가 나간다.

Confirm signup 은 계정이 **아직 확인되지 않았을 때만** 쓰인다.
`Add user` 에서 `Auto Confirm User` 를 켜고 만들었다면 이 템플릿은 나가지 않는다.

**두 곳 모두에 넣어두는 것을 권한다.** 계정이 어느 상태든 같은 메일이 간다.
받은 메일이 `Your sign-in link` 였다면 Magic Link 가 나간 것이므로,
그 템플릿을 고쳐야 화면이 바뀐다.

붙여넣는 곳: **Authentication → Emails → Templates → Magic Link**

| 항목 | 값 |
|---|---|
| Subject | `강점 남기기 로그인 번호` |
| Body | `otp-code.html` 내용 전체 (첫 줄부터 끝까지) |

> 이 파일에는 주석을 두지 않는다.
> Supabase 는 Go 템플릿으로 처리해서 **HTML 주석 안의 `{{ }}` 도 그대로 치환한다.**
> 주석에 설명하려고 적어둔 치환자가 실제 메일에 값으로 박힌다.
> 설명은 전부 이 README 에 적는다.

### 왜 "Magic Link" 템플릿인가

`signInWithOtp()` 로 이미 있는 계정에 코드를 보내면 Supabase 는 **Magic Link** 템플릿을 쓴다.
이름은 링크지만 본문에 `{{ .Token }}` 을 넣으면 **6자리 번호**가 나간다.

> ⚠ `{{ .ConfirmationURL }}` 을 쓰면 번호 대신 링크가 나간다.
> 우리 로그인 화면은 번호를 입력받으므로 맞지 않는다. 템플릿에서 빼둘 것.

### 번호 유효시간

기본 1시간이다. 본문에도 1시간이라고 적혀 있다.
바꾸려면 **Authentication → Sign In / Providers → Email → Email OTP Expiration** 을 고치고
본문 문구도 같이 고친다.

## 색을 바꿨다면

메일 클라이언트는 CSS 변수를 읽지 못해서 색을 직접 적어두었다.
`src/app/globals.css` 의 값을 바꿨다면 이 파일도 같이 바꾸고 다시 붙여넣어야 한다.

| 쓰임 | 값 |
|---|---|
| 번호 상자 | `#2457fc` 글자 / `#eef2ff` 바탕 / `#ccd9fe` 선 |
| 바탕 / 면 | `#f6f7f9` / `#ffffff` |
| 글자 / 보조 / 선 | `#101114` / `#565e6b` / `#d7dbe2` |

## 저장했는데 기본 메일이 그대로 올 때

바꿨는데도 `Your sign-in link` 같은 기본 문구가 오면,
**저장이 안 된 것인지 다른 템플릿을 고친 것인지**부터 가른다. 추측하지 말고 표시를 넣어본다.

1. Magic Link 본문 **맨 위**에 표시를 하나 넣는다.

   ```html
   <p>TEST-1234</p>
   ```

2. **Save** 를 누른다.
3. **페이지를 새로고침**한다.
   - 표시가 사라졌다 → **저장이 안 되는 것이다.** 브라우저를 바꾸거나
     확장 프로그램을 끄고 다시 해본다. 붙여넣기 뒤 편집기 밖을 한 번 클릭하면
     Save 가 활성화되는 경우가 있다.
   - 표시가 남아 있다 → 저장은 됐다. 4번으로.
4. 로그인 화면에서 코드를 다시 받아본다.
   - 메일에 `TEST-1234` 가 보인다 → 이 템플릿이 맞다. 우리 HTML 을 넣으면 된다.
   - 안 보인다 → **다른 템플릿이 쓰이고 있다.** 아래를 본다.

### 다른 템플릿이 쓰이는 경우

계정이 **확인되지 않은 상태**면 Supabase 가 Magic Link 대신
**Confirm signup** 템플릿을 보낸다.

- Authentication → Users 에서 그 계정의 상태를 본다
- 확인되지 않았다면 계정을 지우고 **Add user 로 다시 만들되
  `Auto Confirm User` 를 켠다**
- 또는 Confirm signup 템플릿에도 같은 HTML 을 넣어둔다

## 메일이 오지 않을 때

순서대로 본다.

1. **Authentication → Users 에 그 주소가 있는가**
   앱이 `shouldCreateUser: false` 로 요청하므로 계정이 없으면 **아무것도 보내지 않는다.**
   로그인 화면은 성공·실패를 구분해 보여주지 않으므로(그 주소가 관리자인지 알려주는 신호가 된다)
   화면만 봐서는 알 수 없다. 여기서 확인해야 한다.
2. **SMTP 가 설정돼 있는가**
   Supabase 기본 메일은 시간당 발송 수가 매우 적고 잘 도착하지 않는다.
   Resend 커스텀 SMTP 를 쓴다 (PLAN.md 5장).
3. **Logs → Auth Logs** 에 실제 오류가 남는다.
4. 스팸함.
